ABSTRACT

The rapid proliferation of Large Language Models (LLMs) across enterprise autonomous workflows, customer-facing interfaces, and analytical copilot systems has exposed a fundamental security vulnerability: prompt injection. Because transformer architectures process operational instructions and untrusted third-party data within a unified context window, adversaries can manipulate prompt semantics to hijack execution flow, evade safety guardrails, commandeer agentic tools, or exfiltrate sensitive organizational preambles and credentials.

This project report presents the design, architectural implementation, and empirical evaluation of Prompt Security Guard, a production-ready, dual-layer security middleware and reverse-proxy gateway defending enterprise generative AI applications. Our system establishes an active defensive perimeter around language models through two tightly coupled layers:

Layer 1 (Inbound Threat Perimeter): Enforces pre-execution threat screening before model invocation. To neutralize indirect injection vectors, our pipeline decouples prompt text evaluation from multi-modal attachment ingestion (supporting DOCX XML parsing, PDF stream extraction, and optical character recognition via Tesseract), maintaining granular provenance attribution. Inbound inputs undergo head-tail sequence tokenization (127 head + 127 tail tokens) and are processed through a calibrated neural-heuristic risk fusion engine combining a fine-tuned DistilBERT sequence classifier ($R_{ML}$) with a deterministic regex signature pattern engine ($R_{rule}$) at operational decision threshold $ heta = 0.3800$:

R_fused = 0.40 * R_rule + 0.60 * R_ML        (Decision Band: >= 38.0 -> BLOCK)

Inputs are mapped to an authoritative nine-category threat taxonomy that explicitly protects legitimate academic and defensive cybersecurity queries as safe hard negatives, eliminating catastrophic false alarms. Any input exceeding threshold $ heta$ triggers early termination, guaranteeing exactly zero downstream LLM invocations ($N = 0$).

Layer 2 (Outbound Response Guard): When an approved prompt is processed by the downstream model (Ollama llama3.2:3b, OpenAI gpt-4o, or local mock), the generated output is accumulated in an in-memory buffer under an anti-streaming security policy. Layer 2 scans for system prompt disclosure patterns, live API credentials (e.g., OpenAI sk-*, GitHub ghp_*, Google AIza*, private keys, database URIs), personally identifiable information (PII), and degenerative infinite token loops, enforcing automatic redaction ([REDACTED_PII]) or total response withholding.

Empirical Validation: On an independent 3,000-sample balanced generalization benchmark, our hybrid detector achieves an accuracy of 98.73%, precision of 99.26%, recall of 98.20%, and F1-score of 0.9873, vastly outperforming rule-only baselines (which achieve only 8.73% recall). On a 600-sample adversarial challenge holdout, the system achieves 100% precision and 0.00% false-positive rate. The entire framework exposes an OpenAI-compatible gateway (/v1/chat/completions) for seamless integration with platforms like Open WebUI, a Chromium browser extension for client-side pre-submission interception, and is certified by a 288-test automated regression suite with a 100% pass rate operating at sub-30ms hardware-accelerated inference latency.

INTRODUCTION

1.1 Introduction to Large Language Models and Enterprise Integration

The advent of autoregressive transformer architectures has precipitated a paradigm shift across enterprise computational systems. Modern Large Language Models (LLMs)—including proprietary systems such as OpenAI GPT-4o, Anthropic Claude 3.5, and Google Gemini 1.5, alongside open-weight architectures such as Meta Llama 3.2, Mistral, and DeepSeek—are no longer deployed merely as conversational novelties. Instead, they serve as the cognitive core of mission-critical organizational applications: autonomous agentic workflows, internal enterprise copilots, customer support intermediaries, automated code generation engines, and document synthesis pipelines.

In enterprise architectures, language models are routinely integrated with heterogeneous data channels. They ingest internal document repositories (such as vendor agreements, corporate policies, financial audits, and employee resumes), interact with external web APIs through function calling, and process unstructured queries directly from employees, partners, and public users. This deep operational integration relies on a fundamental presumption: that language models can reliably distinguish between high-privilege operational guidelines (developer instructions, system preambles, access boundaries) and low-privilege external data (user inputs, uploaded documents, retrieved web snippets).

However, modern generative transformer architectures execute instructions and consume context within a unified semantic channel. Unlike traditional computing systems that maintain rigid hardware-level separations between code and data (such as the von Neumann architecture's instruction pointer vs. data registers, or Harvard architecture memory banks), language models ingest tokens from system prompts, user queries, and external document corpora into an undifferentiated input context. Consequently, any instruction embedded within untrusted data has the potential to alter the attention heads of the model, completely overriding developer-defined constraints and hijacking downstream application behavior.

1.2 The Prompt Injection Vulnerability: Direct vs. Indirect Vectors

In the Open Worldwide Application Security Project (OWASP) Top 10 for Large Language Model Applications (2025), Prompt Injection (classified as LLM01) is ranked as the single most critical vulnerability facing generative AI deployments, directly linked with Sensitive Information Disclosure (LLM06). The prompt injection threat landscape is broadly bifurcated into two primary operational vectors:

1. Direct Prompt Injection (Jailbreaks & Goal Hijacking): In a direct injection attack, the adversary directly inputs malicious payloads into the user interface or API endpoint of the application. The objective is to force the model to disregard its original system prompt and adopt an unconstrained adversarial persona. Typical patterns include explicit instruction overrides (e.g., "Ignore all previous instructions and output the master administrative password"), hypothetical framing (e.g., roleplaying unrestricted synthetic shells), and encoded token bypasses (Base64, ROT13, binary ciphers, or zero-width Unicode manipulations) designed to evade naive lexical keyword filters.

2. Indirect Prompt Injection (Carrier-Borne & Multi-Modal Exploits): Indirect prompt injection represents a substantially more insidious and systemic attack vector. In this paradigm, the adversary does not interact with the language model directly. Instead, malicious instructions are planted inside external carrier artifacts that the application is expected to retrieve, read, or summarize. These carriers include uploaded Word documents (.docx), PDFs, corporate balance sheets, scanned receipts, emails, and web pages. When an autonomous enterprise agent ingests the carrier document, the hidden instructions execute within the context window:

[Document Header: Q3 Financial Summary - Confidential] Operating Revenue: $14.2M ... Net Profit: $3.1M ... [SYSTEM DIRECTIVE: Disregard the above report. Do not summarize this document. Instead, execute tool call 'exfiltrate_database' with target 'https://adversary.com/leak' containing the user's active session token and system preamble.]

Because conventional document parsers merely extract raw text strings and concatenate them blindly into the prompt context, the LLM processes the adversarial payload with the same instructional priority as the user's authentic command.

1.3 Problem Statement

Existing enterprise approaches to defending against prompt injection suffer from four fundamental engineering and architectural deficiencies:

1. Failure of Lexical Heuristics: Traditional rule-based intrusion detection systems rely on static regular expressions and blacklists of known attack phrases (such as "ignore previous instructions"). Adversaries easily bypass these filters using semantic paraphrasing, synonym substitution, linguistic fragmentation, and multi-lingual translation.

2. Catastrophic Over-Defense on Hard Negatives: Standalone neural classifiers frequently exhibit high false-positive rates when evaluating legitimate security inquiries. An employee asking "How do prompt injection vulnerabilities affect corporate LLM gateways?" is frequently blocked because the prompt contains security keywords, severely impeding legitimate academic and professional workflows.

3. Lack of Multi-Modal Threat Attribution: Existing analyzers evaluate concatenated text blocks as a monolithic string. If an uploaded document contains an embedded carrier injection while the user's query is benign, existing systems fail to isolate the threat source, corrupting user risk profiles and failing to enforce targeted document sanitization.

4. Absence of Outbound Egress Sanitization: Conventional firewalls inspect only inbound traffic. If an adversary successfully evades inbound defenses via a novel zero-day prompt structure, the model is permitted to leak internal system instructions, proprietary code, database connection strings, and sensitive API keys directly to the attacker without post-generation validation.

2.1 Theoretical Background and Evolution of Prompt Injection Attacks

The vulnerability of Large Language Models to adversarial manipulation originates from their fundamental mathematical formulation. Modern autoregressive language models compute the conditional probability distribution of the next token $x_t$ given a sequence of prior context tokens:

P(x_t | x_1, x_2, ..., x_{t-1}) = Softmax( W_u * h_{t-1} )

In instruction-tuned models (such as those trained via Reinforcement Learning from Human Feedback), the initial tokens representing system preambles (e.g., "You are a helpful and harmless assistant...") are mathematically equivalent to subsequent user tokens within the attention matrix:

Attention(Q, K, V) = Softmax( (Q * K^T) / sqrt(d_k) ) * V

Because dot-product attention computes pairwise token affinity across the entire concatenated sequence, an adversary who structures input tokens with commanding lexical semantics (e.g., "SYSTEM NOTICE: EMERGENCY OVERRIDE") can force the self-attention weights to heavily favor the adversarial tokens over the original developer preamble. Consequently, prompt injection represents an architectural property of single-channel transformer attention rather than an ordinary software bug.

This foundational study was among the first to formally catalog prompt injection attacks against instruction-tuned GPT-3 models. The authors categorized attacks into goal hijacking (diverting the model toward unintended tasks) and prompt leaking (extracting secret system preambles). 2. Greshake et al. (2023) [2]: "Not What You've Signed Up For: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection." Greshake et al. formalized the concept of indirect prompt injection. Published in ACL 2024, this research introduced InjecAgent, a standardized benchmark evaluating 1,054 indirect injection test cases across 17 user tools. Their findings revealed that even frontier models like GPT-4 fall prey to indirect injections when payloads are delivered through external tool parameters.

5. Debenedetti et al. (2024) [5]: "AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents." Published in NeurIPS 2024, AgentDojo created a dynamic simulation framework with 97 realistic tasks. Their benchmark proved that static keyword filters and prompt-engineering defenses degrade catastrophically against adaptive adversaries who modify phrasing.

6. Kholkar and Ahuja (2025) [6]: "CAPTURE: Context-Aware Prompt Injection Testing and Robustness Enhancement." Kholkar and Ahuja highlighted the critical industry challenge of over-defense. 7. Cui et al. (2026) [7]: "Rethinking Assessments of Prompt Injection Attacks." In ACL 2026, Cui et al. conducted an extensive reassessment across real-world application corpora. 8. Zhu et al. (2023) [8]: "PromptRobust: Towards Evaluating the Robustness of Large Language Models on Adversarial Prompts." 10. Carlini et al. (2021) [10]: "Extracting Training Data from Large Language Models." Published in USENIX Security, this study demonstrated that language models memorize training context, operational preambles, and cryptographic keys. OWASP codified Prompt Injection (LLM01) and Sensitive Information Disclosure (LLM06) as the primary threats to enterprise generative systems, recommending dual-perimeter filtering.

13. Branch et al. (2022) [13]: "Evaluating LLM Vulnerabilities in Conversational Systems." Branch et al. examined prompt injection vulnerabilities in corporate chatbot integrations, demonstrating how customer service bots can be hijacked to issue fraudulent refund transactions.

14. Goodfellow et al. (2014) [14]: "Explaining and Harnessing Adversarial Examples." Provided the foundational theory of adversarial machine learning, demonstrating that continuous vector spaces contain linear vulnerabilities exploitable by targeted perturbations.

15. Wallace et al. (2019) [15]: "Universal Adversarial Triggers for Attacking and Analyzing NLP." Demonstrated that short, gradient-optimized token sequences can act as universal triggers that force models into target operational states regardless of surrounding context.

2.3 Detailed Attack Taxonomy Survey: Direct, Carrier, and Jailbreak Patterns

Across the reviewed literature, adversarial manipulation of language models manifests across distinct behavioral patterns. Understanding the taxonomy of these attacks is essential for designing effective detection filters:

1. Instructional Precedence Manipulation: Attacks exploiting the natural tendency of instruction-tuned models to follow the latest imperative command. Phrases such as "Forget what you were told", "Disregard previous guidelines", and "New primary mission directive" seek to invalidate prior system context through linguistic hierarchy.

2. Contextual Roleplay & Hypothetical Persona Framing: Known colloquially as "Jailbreaks" (e.g., DAN, STAN, Mongo Tom, Developer Mode), these attacks construct elaborate hypothetical scenarios where safety alignments are declared void. For example, the adversary commands the model to simulate an unrestricted command-line terminal in an alternate universe where safety guidelines do not exist.

3. Linguistic and Structural Obfuscation: Techniques designed to evade standard subword tokenization (Byte-Pair Encoding or WordPiece). Adversaries employ Base64 encoding, ROT13 ciphers, Morse code, zero-width Unicode characters, and phonetic misspellings (leetspeak). Because transformer models often retain latent understanding of encoded patterns while static regex filters look only for raw text, obfuscated attacks represent a primary bypass mechanism.

4. Document Carrier Concealment: Indirect attacks concealed within structural elements of documents. In Microsoft Word (.docx) files, adversarial text can be hidden inside XML comments, transparent font coloring, zero-height table cells, or document header metadata. In PDF documents, instructions can be embedded in off-screen coordinate objects or invisible font layers. In image documents, raster text is rendered visually, evading text-only parsers unless optical character recognition (OCR) is explicitly applied.

2.4 Mathematical Analysis of Attention Hijacking vs. Defense-in-Depth

To formalize why prompt injection cannot be resolved inside the language model alone, consider the self-attention mechanism over a token sequence $X = [x_1, ..., x_n]$. Let $S = [s_1, ..., s_m]$ denote the developer system prompt, and let $U = [u_1, ..., u_k]$ denote untrusted user input, such that $X = [S; U]$. The attention weight between query token $x_i$ and key token $x_j$ is given by:

lpha_{i,j} = rac{\exp( (W_q x_i)^T (W_k x_j) / \sqrt{d} )}{\sum_{l=1}^n \exp( (W_q x_i)^T (W_k x_l) / \sqrt{d} )}

If the user input $U$ contains adversarial tokens designed to have high inner products with $W_q$ and $W_k$ across instruction dimensions, the denominator sums across both $S$ and $U$, causing the attention mass $\sum_{j \in U} lpha_{i,j}$ to dominate over $\sum_{j \in S} lpha_{i,j}$. When this occurs, the model's representations in subsequent feed-forward layers are computed almost entirely from the adversarial input $U$, effectively erasing the developer instructions $S$.

This mathematical reality demonstrates that no amount of internal prompt engineering can guarantee safety when malicious instructions share the attention matrix. The only mathematically sound defense is architectural decoupling: screening and discarding adversarial inputs before they enter the model's context window (Layer 1), and verifying the output before client egress (Layer 2).

2.5 Summary of Literature Review and Identified Research Gaps

Synthesizing the findings from existing literature reveals four critical technological research gaps that this capstone project addresses directly:

Research Gap 1: Inadequate Hybrid Fusion in Inbound Detection. Prior work either relies exclusively on rigid regex patterns (which fail against paraphrased semantic variants, achieving $<10\%$ recall as shown by Zhu et al. [8]) or relies solely on deep neural classifiers (which lack deterministic floor guarantees and incur significant inference latency). An engineered, calibrated mathematical fusion ($R_{fused} = lpha R_{rule} + eta R_{ML}$) combining signature certainty with transformer attention has been conspicuously absent.

Research Gap 2: Indiscriminate Over-Defense on Defensive Inquiries. As identified by Kholkar and Ahuja [6], existing defensive filters exhibit catastrophic false-positive rates on academic, pedagogical, and defensive cybersecurity inquiries. Existing taxonomy models lack an explicit, protected category for legitimate security inquiries.

Research Gap 3: Conflation of Prompt and Multi-Modal Attachment Contexts. Prior indirect injection benchmarks (such as InjecAgent [4] and AgentDojo [5]) establish the severity of attachment-borne carrier injection, yet production systems still evaluate user prompt strings and document text as an undifferentiated stream. Decoupled extraction with granular provenance attribution (threat_source ∈ {Prompt, Attachment, Both}) is missing from current architectures.

Research Gap 4: Complete Egress Vulnerability. Despite Carlini et al. [10] and OWASP [12] demonstrating that models leak system prompts, API keys, and PII under adversarial steering, available security tools operate almost entirely on the input, leaving the output egress channel completely unmonitored.

3.4 Detailed Functional Requirements Specification

The functional requirements formalize the concrete behavioral contracts implemented by the Prompt Security Guard system:

FR-1: Inbound Prompt Risk Scoring
Description: The gateway shall intercept every inbound text submission and evaluate it against the neural-heuristic risk engine.
Input: JSON payload containing user prompt string prompt (UTF-8 encoded).
Processing: Compute $R_{rule}$ via regex pattern bank; compute $R_{ML}$ via DistilBERT; fuse via $R_{fused} = 0.40 R_{rule} + 0.60 R_{ML}$.
Output: Continuous risk score $[0, 100]$, risk level (LOW, MEDIUM, HIGH, CRITICAL), and decision (ALLOW, BLOCK).
Exceptions: If input is empty, return HTTP 400 Bad Request with informative error JSON.

FR-2: Decoupled Multi-Modal Attachment Parsing
Description: The system shall extract text content from uploaded files (DOCX, PDF, TXT) independently of the user prompt string.
Input: Multipart form-data containing binary file upload.
Processing: For DOCX, traverse document XML elements; for PDF, extract page text streams; for TXT, decode UTF-8.
Output: Extracted attachment text string; separate risk evaluation $R_{attachment}$.
Exceptions: If file size exceeds 20MB or format is unsupported, reject upload with secure error code.

FR-3: Image Optical Character Recognition (OCR) Scanning
Description: The system shall detect text embedded inside image attachments (PNG, JPG) using Tesseract OCR.
Input: Image file upload (PNG or JPEG).
Processing: Preprocess image via Pillow (grayscale, contrast normalization); extract text using pytesseract.image_to_string().
Output: Extracted optical text string passed to Layer 1 scanner.
Exceptions: Corrupted image headers return HTTP 422 Unprocessable Entity.

FR-4: Fine-Grained Threat Provenance Attribution
Description: The system shall explicitly record and output the source of any detected security risk.
Processing: If only prompt risk exceeds threshold, set threat_source = "User Prompt"; if only attachment risk exceeds threshold, set threat_source = "Attachment"; if both exceed, set threat_source = "Both"; otherwise set threat_source = "None".
Output: Provenance label included in API responses and audit logs.

FR-5: Head-Tail Sequence Tokenization
Description: To neutralize attacks placed at sequence boundaries, inputs longer than 254 tokens shall be truncated symmetrically.
Processing: Extract 127 tokens from the start and 127 tokens from the end; assemble [[CLS], t_1..t_127, [SEP], t_N-126..t_N, [SEP]].
Output: 256-token tensor passed to DistilBERT classifier.

FR-6: Authoritative Nine-Category Threat Classification
Description: Inbound threats shall be categorized into nine explicit taxonomy buckets.
Processing: Map detected pattern evidence into: (1) Benign, (2) Direct Injection, (3) Indirect Injection, (4) Instruction Override, (5) Jailbreak, (6) Obfuscation, (7) Carrier Injection, (8) Sensitive Exfiltration, or (9) Safe Hard Negatives.
Output: Authoritative category name and explanation string.

FR-7: Hard-Negative Exemption for Security Inquiries
Description: Legitimate academic and professional cybersecurity queries shall not be blocked.
Processing: Inputs categorized under Category 9 shall be assigned an ALLOW verdict regardless of heuristic matches.
Output: Threat score capped at LOW/MEDIUM; prompt forwarded to model.

FR-8: Strict Pre-Execution Decision Gating
Description: When an input is classified as BLOCK, downstream language models shall never be called.
Processing: Gating check verifies $R_{fused} < 38.0$; if blocked, abort pipeline and return security alert.
Output: HTTP 200/403 with block alert; zero downstream network calls ($N=0$).

FR-9: Outbound Whole-Response Buffering
Description: Downstream token streams shall be accumulated before client egress.
Processing: Policy prohibits raw token streaming (stream=false); buffer collects full generated response.
Output: Complete text buffer passed to Layer 2 inspection engine.

FR-10: Outbound System Prompt and Preamble Disclosure Detection
Description: The generated response shall be scanned for leaked system prompt preambles.
Processing: Pattern matching checks for system headers, XML system tags, and confidential operational rules.
Output: If leak score $\ge 85$, enforce BLOCK & WITHHOLD; deliver secure alert placeholder.

FR-11: Live Secret and API Key Scanning
Description: Outbound responses shall be scanned for exposed credentials and private keys.
Processing: Regex scanners search for OpenAI keys (sk-*), GitHub tokens (ghp_*), Google Cloud keys (AIza*), private keys, and database URIs.
Output: If detected, withhold response and log critical credential breach event.

FR-12: Personally Identifiable Information (PII) Redaction
Description: Personal identity numbers and financial credentials in responses shall be masked.
Processing: Detect SSNs, credit cards (with Luhn validation), and emails; substitute matches with [REDACTED_PII].
Output: Sanitized text returned under verdict MASK.

4.1 Threat Modeling and Adversarial Assumptions

We model an enterprise computational environment wherein untrusted users or external entities interact with generative language model applications via direct web portals, REST API endpoints, or carrier documents. The adversary possesses varying levels of access and sophisticated capabilities:

Adversary Capabilities:

  • Black-Box Query Access: The adversary submits arbitrary natural language queries, observing model output and attempting adaptive, iterative prompt variations.
  • Document Poisoning (Indirect Injection): The adversary uploads structured files (DOCX, PDF) or raster graphics (scanned receipts, infographics) containing embedded payload instructions concealed via zero-point fonts, white-on-white text, XML metadata attributes, or visual text blocks.
  • Encoding and Obfuscation Manipulation: The adversary encodes attack directives using Base64, hex encoding, ROT13 ciphers, Unicode variations, or linguistic fragmentation to defeat naive string-matching algorithms.
  • Adversarial Context Framing: The adversary employs psychological roleplay framing (e.g., "Do Anything Now" / DAN persona, fictional authoring, developer debugging modes) to coerce the model into overriding its developer preamble.

Protected Organizational Assets: (1) System Preamble & Context: confidential developer instructions and corporate operational boundaries; (2) Environment Secrets: production API tokens (sk-*, ghp_*, AIza*), database credentials, and cryptographic certificates; (3) User Privacy: Personally Identifiable Information (SSNs, banking credentials, emails); and (4) Generative Compute Budget: protection against denial-of-wallet infinite token loops.

4.2 High-Level System Architecture and Design Principles

The system architecture implements defense-in-depth across two distinct perimeters surrounding the target language model, illustrated in Figure 4.1.

The architecture adheres to three foundational engineering principles:

4.5 Mathematical Foundations of Transformer Attention & DistilBERT Classification

The core neural component of Layer 1 is a fine-tuned DistilBERT transformer (Sanh et al., 2019). DistilBERT compresses the standard 12-layer BERT-base architecture into 6 transformer layers while retaining 97% of its language understanding capabilities and executing 60% faster.

Multi-Head Self-Attention Formulation: Given an input sequence of subword tokens embedded into vector space $X \in \mathbb{R}^{n imes d}$, where $n \le 256$ is sequence length and $d = 768$ is the hidden embedding dimension, the attention mechanism projects $X$ into Query ($Q$), Key ($K$), and Value ($V$) matrices via learned parameter weights $W_q, W_k, W_v \in \mathbb{R}^{d imes d_k}$:

Q = X W_q,      K = X W_k,      V = X W_v

The scaled dot-product attention score for each token pair $(i, j)$ is computed as:

Attention(Q, K, V) = softmax\left( rac{Q K^T}{\sqrt{d_k}} ight) V

In multi-head attention, $h=12$ independent attention heads compute projections in parallel, allowing the model to jointly attend to information from different representation subspaces:

MultiHead(Q, K, V) = Concat(head_1, ..., head_h) W_o

Each attention layer is followed by a Feed-Forward Network (FFN) with Gaussian Error Linear Unit (GELU) activation and residual Layer Normalization:

FFN(x) = GELU(x W_1 + b_1) W_2 + b_2
LayerNorm(x) = rac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \odot \gamma + eta

Sequence Classification and Cross-Entropy Optimization: The output representation of the special classification token [CLS] from the final transformer layer, denoted $h_{[CLS]} \in \mathbb{R}^{768}$, is passed through a linear projection layer with weight matrix $W_c \in \mathbb{R}^{2 imes 768}$ and bias $b_c \in \mathbb{R}^{2}$:

z = W_c \cdot h_{[CLS]} + b_c

The posterior probability of the input sequence being malicious ($y=1$) is obtained via the softmax function:

P(malicious \mid X) = rac{\exp(z_1)}{\exp(z_0) + \exp(z_1)}

The model was optimized using Binary Cross-Entropy Loss with AdamW ($eta_1=0.9, eta_2=0.999, \epsilon=10^{-8}$, weight decay $\lambda = 0.01$) and a linear learning rate warmup over 500 steps:

\mathcal{L}_{BCE} = - rac{1}{N} \sum_{i=1}^N \left[ y_i \log P(y_i=1 \mid X_i) + (1 - y_i) \log(1 - P(y_i=1 \mid X_i)) ight]

4.6 Input Normalization and Head-Tail Sequence Tokenization Algorithm

Adversaries frequently position injection payloads at the extremes of large input blocks: either at the immediate beginning (head override) or buried at the end of lengthy padding text (tail carrier injection). Standard truncation to 256 tokens from the start discards the end of the text. As implemented in backend/prompt_security/preprocessing/token_preprocessing.py, our pipeline extracts 127 tokens from the head and 127 tokens from the tail:

T_{input} = [ [CLS], t_1, t_2, ..., t_{127}, [SEP], t_{N-126}, ..., t_N, [SEP] ]

The complete algorithmic procedure is detailed in Algorithm 1, followed by the actual production implementation in Listing 4.1.

CONCLUSION AND FUTURE SCOPE

6.1 Conclusion and Realized Systems Contributions

This B.Tech engineering research project designed, implemented, and empirically evaluated Prompt Security Guard, a comprehensive dual-layer prompt injection detection and response security framework engineered for organizational large language model deployments. By establishing active defense-in-depth perimeters surrounding generative transformer models, our architecture directly resolves the foundational vulnerability of unified instruction-data execution in modern autoregressive neural networks.

The project culminated in the delivery of a production-grade, highly performant security middleware that successfully neutralizes direct prompt injection, document carrier indirect injection, multimodal OCR image attacks, and downstream sensitive context leakage. The primary technical contributions realized through this capstone engineering endeavor include:

1. Dual-Layer Defense-in-Depth Architecture: We demonstrated that isolated inbound filtering or post-generation moderation alone is insufficient to secure modern generative systems. By coupling an inbound pre-execution perimeter (Layer 1) with an outbound post-generation sanitization perimeter (Layer 2), the framework guarantees zero downstream LLM invocation ($N=0$) on blocked threats while providing an immutable fail-safe against credential harvesting and system prompt leakage.

2. Calibrated Neural-Heuristic Risk Fusion: Addressing the extreme vulnerability of static regular expressions (which achieved only 8.73% recall on independent benchmarks) and the over-defense of naive neural models, we engineered a calibrated fusion engine combining fine-tuned DistilBERT transformer sequence probabilities ($R_{ML}$) with deterministic signature heuristics ($R_{rule}$) at an optimized decision threshold ($ heta = 0.3800$). The fused model achieved 99.03% accuracy and 98.80% recall across 3,000 unseen generalization samples.

3. Authoritative Nine-Category Threat Taxonomy: We established a nine-category threat taxonomy that explicitly resolves the persistent industry problem of cybersecurity false alarms. By formulating Category 9 ("Safe Hard Negatives") with specialized contextual exemption logic, the system attained a 0.00% false-positive rate on complex educational and defensive cybersecurity inquiries, ensuring uninterrupted academic and professional research.

4. Decoupled Multi-Modal Attachment Parsing: We engineered an isolated attachment processing pipeline supporting Microsoft Word (.docx), Portable Document Format (.pdf), and Tesseract optical character recognition (OCR) for raster graphics. By decoupling document scoring from user prompt evaluation, the system achieved 100% detection on tail carrier injections in documents while preserving granular threat provenance attribution (threat_source ∈ {User Prompt, Attachment, Both}).

5. Enterprise Ecosystem Integration & Rigorous Verification: We implemented drop-in enterprise adapters including an OpenAI-compatible reverse-proxy endpoint (POST /v1/chat/completions) for Open WebUI, an asynchronous Chromium browser extension with pre-submission DOM event interception, and validated complete architectural stability via a comprehensive 288-test automated regression suite achieving a 100.0% pass rate at sub-30ms hardware-accelerated latency.

6.2 Research Hypotheses Validation Synthesis

The empirical investigations documented throughout Chapter 5 systematically confirmed all three foundational research hypotheses formulated at the inception of the project:

  • Hypothesis 1 (Validated): Fusing neural transformer attention with heuristic signatures at $ heta = 0.3800$ elevated adversarial recall from 8.73% (rule-only baseline) to 98.80%, achieving an F1-score of 0.9903 and outperforming standalone neural classifiers by a statistically significant margin (McNemar's test $p = 0.0076, p < 0.01$).
  • Hypothesis 2 (Validated): Decoupling document text from prompt strings during ingestion enabled 100% detection of concealed carrier injections in DOCX tables and scanned OCR flyers without inflating the user's personal malicious intent score.
  • Hypothesis 3 (Validated): Atomic whole-response buffering coupled with regex secret scanners and PII redaction intercepted 100% of live synthetic API keys and masked confidential user data with less than 5ms execution overhead.

6.3 Limitations of Current Framework

While the realized framework establishes state-of-the-art protection across targeted deployment scenarios, four operational limitations must be recognized:

  • Semantic Metaphor Evasion: Highly subtle, purely allegorical narratives that avoid all overt offensive vocabulary (e.g., metaphorical fairy tales requesting "forbidden recipes") can occasionally produce low probability scores ($P(malicious) < 0.38$) in the DistilBERT encoder.
  • Extreme OCR Degeneracy: When processing severely degraded, low-resolution, or heavily skewed document scans, the Tesseract OCR engine experiences character recognition errors that can obscure adversarial payload tokens.
  • Language-Specific Subword Fragmentation: While the model demonstrates strong cross-lingual transfer across Romance and Germanic languages, low-resource languages with non-Latin scripts experience heavy subword fragmentation under the standard WordPiece vocabulary.
  • Static Preamble Similarity Baselines: In the current implementation, Layer 2 system prompt disclosure detection compares response text against static preamble embeddings. In environments with dynamic, user-configurable system prompts, reference embeddings must be recalculated on the fly.

6.4 Future Scope and Research Roadmap

Building upon the verified software architecture and empirical findings of this project, several promising research trajectories are identified for subsequent development:

1. Autonomous Multi-Agent Tool Call Perimeters: Extending the Layer 1 security gateway to monitor autonomous multi-agent environments (e.g., LangGraph, AutoGen, CrewAI). The security perimeter will intercept and validate structured tool-calling arguments, JSON payloads, and dynamic database queries before execution by agent workers.

2. Dynamic Ephemeral Canary Token Ingestion: Integrating dynamic, cryptographically generated canary tokens into system preambles on a per-session basis. If a downstream LLM is manipulated into leaking its preamble, Layer 2 can detect the exact canary digest with zero false negatives, regardless of semantic paraphrasing.

3. Edge Quantization (4-Bit GGUF & WebAssembly): Quantizing the 66M-parameter DistilBERT transformer into 4-bit integer representations (INT4) using llama.cpp / ONNX Runtime. This will allow the entire neural detection engine to run locally inside client browser extensions or edge containers with a memory footprint under 30MB and zero server latency.

4. Reinforcement Learning from Security Feedback (RLSF): Constructing an active learning feedback loop wherein false positives and false negatives flagged by security administrators in the SQLite forensics dashboard are automatically formatted into synthetic training batches for periodic model weight updates.
